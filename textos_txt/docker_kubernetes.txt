Pods

Containers within a pod can communicae via { Localhost, IPC
Pods are ephemeral
Deploying a pod is an atomic operation , it succeed or not
If a pod fail , it is replaced with a new one with a shiny new ip address
You don't update a pod, you replace it with an update version
you sacale by adding more pods, not more containers in a pod
Pods são a pates que exeutam um ou mais containers

storage - the static way

PVC Persistent volumes and claims
-persistent volumes
 -represent a storage resource
 -cluster wide
 -provisioned by an administrator
-persitent volue claim
 -A one-to-one mapping to a persistent volume
-one or more pods can use a persistent volume claim
-can be consumed by any of the containers within the pod

Reclaim policies
Delete
 -Delete the data upon pods deletion
  -the default
 -Retain
  -keeps the data upon pods deletion

Acess Modes
-ReadWriteMany
 -the volume can be mounted as read-write by many pods
-RedOnlyMany
 -the volume can be mounted read-only by many pods
-ReadWriteOnce
 -The volume can be mounted as read-write by a single pod
 -the other pods are in read-only mode
 -the one that has mounted the volume first will be able to write

hostPath is a plugin allowing local storage on the node
hostPath works only on single-node clusters

Persistent Volume states
-Available
  -a free resource that is not yet bound to a claim
-Bound
  -the volume is bound to a claim
-released
  -the claim has been deleted but the resource is not yet reclaimed by the cluster
-failed
  -the volume has failed is automatic reclamation

Horizontal Pod Auto scaling

-uses the k8s metric server
-pod must have request and limits defined
-the HPA checks the Metrics Server every 30 seconds
-scale according to the min and max number or replicas
-Cooldown/delay
  -Prevent racing conditions
  -Once a change has been made, HPA waits
  -By default, the delay on scale up events is 3 minutes and the delay on scale down event is 5 minutes
